**Message passing**: procesos con memoria **local** que se comunican enviando/recibiendo mensajes. **MPI** es el API estándar (MPI Forum, 1.0 en 1994) para C, C++ y Fortran; implementaciones MPICH y OpenMPI. Paralelismo **explícito**; funciona en CPU, nodo, NUMA y cluster, y admite híbrido (MPI + OpenMP).

## Estructura de un programa

```cpp title="ejemplo01.cpp" {7-10,25}
#include <mpi.h>
#include <iostream>
using namespace std;

int main(int argc, char *argv[]) {
  int ierr, rank, size, dato = 10;
  ierr = MPI_Init(&argc, &argv);            // una sola vez, al inicio
  MPI_Comm_size(MPI_COMM_WORLD, &size);     // número total de procesos
  MPI_Comm_rank(MPI_COMM_WORLD, &rank);     // mi id: 0..size-1
  if (ierr == MPI_SUCCESS)
    cout << "Hola mundo desde el proceso " << rank << " de " << size << endl;

  if (rank == 2) dato = 20;                 // cada proceso tiene SU copia de dato
  cout << "Proceso " << rank << " tiene dato = " << dato << endl;

  double time = MPI_Wtime();                // reloj en segundos (double)
  cout << "Tiempo del proceso " << rank << " = " << time << endl;
  MPI_Finalize();
}
```

```bash
mpic++ -o ejemplo01 ejemplo01.cpp     # C: mpicc · Fortran: mpif90
mpirun -np 4 ./ejemplo01
```

:::note[Handles y errores]
`MPI_COMM_WORLD` es el comunicador predefinido con **todos** los procesos (numerados desde 0 en `rank`). Las rutinas devuelven un entero; `MPI_SUCCESS` indica éxito. `MPI_Abort(comm, err)` termina todos los procesos.
:::

## Punto a punto

```text
MPI_Send(&buffer, count, datatype, dest,   tag, comm)
MPI_Recv(&buffer, count, datatype, source, tag, comm, &status)
```

- El mensaje es un **array de `count` elementos de `datatype`** (MPI_INT, MPI_FLOAT, MPI_DOUBLE, MPI_CHAR, MPI_BYTE, MPI_PACKED…). El tipo enviado debe coincidir con el recibido (soporte para arquitecturas heterogéneas).
- El recibo se confirma si **source, dest y tag** corresponden (count y datatype no garantizan el emparejamiento). Comodines: `MPI_ANY_SOURCE`, `MPI_ANY_TAG`.
- `status.MPI_SOURCE`, `status.MPI_TAG`, `MPI_Get_count(&status, type, &count)`.

```cpp title="ejemplo02.cpp (fragmento)" {5,9}
if (rank == 0) {
    numero = 10;
    MPI_Send(&numero, 1, MPI_INT, 1, 0, MPI_COMM_WORLD);
    for (int i = 0; i < 10; i++) arr_numero[i] = i;
    MPI_Send(arr_numero, 10, MPI_INT, 1, 0, MPI_COMM_WORLD);   // un array: count = 10
} else if (rank == 1) {
    MPI_Recv(&numero, 1, MPI_INT, 0, 0, MPI_COMM_WORLD, &estado);
    MPI_Recv(arr_numero, 10, MPI_INT, 0, 0, MPI_COMM_WORLD, &estado);
}
```

## Modos de envío (bloqueantes)

| Rutina | Se completa cuando… |
|---|---|
| `MPI_Ssend` (síncrono) | el receptor **empezó a recibir** (acuse de recibo) |
| `MPI_Bsend` (buffered) | siempre de inmediato: copia a un buffer del usuario (`MPI_Buffer_attach/detach`) |
| `MPI_Send` (standard) | síncrono **o** buffered según la implementación (mensaje chico ⇒ buffer; grande ⇒ síncrono) |
| `MPI_Rsend` (ready) | de inmediato; si el receptor no estaba listo ⇒ error. Solo si el performance es crítico |
| `MPI_Recv` | el mensaje llegó al buffer |

:::caution[Error común]
«`MPI_Send` nunca bloquea». **No se debe asumir** que el envío se complete antes de que empiece el `Recv`: con mensajes grandes se comporta como `Ssend`. Ver [bloqueo mutuo](/mpi/bloqueante/).
:::

:::tip[En el examen…]
Cada Send necesita **su** Recv con el mismo (fuente, destino, tag). Si un proceso manda dos mensajes al mismo destino, usa **tags distintos** o respeta el orden (los mensajes entre un par con el mismo tag no se adelantan).
:::

## Ejercicio

¿Qué imprime `ejemplo02.cpp` con `mpirun -np 3`? ¿Por qué el `fprintf` después de `MPI_Abort` puede no aparecer?

<Solucion>

Con `size > 2`, el rank 0 llama a `MPI_Abort(MPI_COMM_WORLD, -1)`, que **termina todos los procesos** del comunicador inmediatamente; el `fprintf` está *después* del abort, así que normalmente no se imprime (debería ir antes). Los ranks 1 y 2 no hacen nada (el `else` solo se ejecuta si `size ≤ 2`) y son abortados.

</Solucion>
